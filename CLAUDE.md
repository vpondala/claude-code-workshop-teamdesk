# CLAUDE.md

Teamdesk: Bun + Turborepo monorepo (`apps/web`, `packages/db`, `packages/services`) on Cloudflare Workers + D1. Request path: route → tRPC router → `@repo/services/<module>` → `@repo/db/<module>`. Only the rules below are non-obvious; read the code for the rest.

## Commands

- `bun run dev` applies migrations and `packages/db/seed.sql` to a local D1 in `apps/web/.wrangler`. To reset data, delete that folder; there is no reset script.
- `bun test` runs against in-memory `bun:sqlite` with the real migrations, so a schema change without a generated migration fails tests, not just deploys.
- `bun run check` = Ultracite (Biome) lint + typecheck. Run it before calling work done: the pre-commit hook only runs `fix`, which won't catch type errors.
- After any change to `packages/db/src/schema.ts`, run `bun run generate` in `packages/db` and commit `migrations/` including `migrations/meta/`. Wrangler applies migrations, not drizzle-kit, so a schema edit without this never reaches D1, and missing `meta/` breaks the next generate.
- Typecheck depends on the `Env` type that `bun run cf-typegen` writes from `wrangler.jsonc`. Rerun it after touching bindings, or `env.DB` types go stale.

## Browser/server split

- Browser code may import only `@repo/db/shared`. Every other `@repo/db` / `@repo/services` entry pulls in drizzle, which breaks the client bundle. Anything the UI needs (types, limits like booking min/max minutes, `MAX_BOOKINGS_PER_MEMBER_PER_DAY`) goes in `packages/db/src/shared.ts`.
- tRPC has no transformer, so results must be plain JSON. Return ISO strings, never `Date`: a `Date` arrives as a string over HTTP but stays a `Date` during SSR (in-process link), so the two paths disagree.
- Procedures use `ctx.services`, never `ctx.env`. Over HTTP Hono adds `env` to ctx, but the SSR path does not.

## Adding a module

- No barrel files. A new table gets `packages/db/src/<name>.ts` plus an `exports` line in `packages/db/package.json`, or the import won't resolve.
- A new service gets `packages/services/src/<name>.ts` and a line in `createServices` in `apps/web/src/server/trpc/context.ts`, the only place `env.DB` is read. Without that line the service isn't on `ctx`.
- Templates: `packages/db/src/notes.ts` and `bookings.ts`, `packages/services/src/notes.ts`.

## Layer rules

- DB query functions take any drizzle SQLite instance (`Database`) so the same code runs on D1 (async) and `bun:sqlite` (sync, in tests). Don't use driver-specific APIs. No validation or business rules there; return plain JSON and keep row types private.
- Services (`createXService(db)`) validate with zod and throw `NotFoundError` / `ValidationError` / `ConflictError` / `ForbiddenError`. `init.ts` maps these to tRPC codes; any other throw becomes a 500 with its message hidden in production.
- Service methods are `async` even when they don't await, so a zod failure rejects instead of throwing synchronously past the caller's `.catch`.
- Export the input schema for the router to use, and parse it again inside the service, because services are also called directly (tests, SSR) without the router's check.
- Routers stay thin: input schema from the service, one service call. Rules live in services so tests cover them without tRPC.

## Auth and permissions

- There is no sign-in: `ctx.userId` is always null and `protectedProcedure` always answers UNAUTHORIZED. Don't use it for team features.
- Instead, mutations take the acting member's id (`actorId`, from the page's member picker) as the first argument and check it with `requireMember` / `requireAdmin`. Forgetting the check lets anyone act as anyone.

## Data conventions

- Timestamps are UTC ISO 8601 text, so string comparison orders them correctly. Task `dueOn` is a plain `YYYY-MM-DD` with no time zone.
- Booking slots are half-open `[startsAt, endsAt)`, so back-to-back bookings don't clash. Use `<` / `>`, not `<=`, in overlap checks.
- Bookings are cancelled by setting `cancelledAt`, never deleted, so history and limits stay correct. Queries for active bookings must filter `cancelledAt is null`.
- A partial unique index on `(roomId, startsAt) where cancelledAt is null` backs up the service-level overlap check against races. Keep both; the index alone misses overlaps with different start times.

## Generated files

- `apps/web/src/routeTree.gen.ts` is generated by TanStack Router; don't edit it by hand.
- Web imports use `#/*` for `apps/web/src/*`.
